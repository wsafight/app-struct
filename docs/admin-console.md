# Operations Administration Console

Auth-enabled projects include an `/admin` page and a matching `GET /api/admin/overview` endpoint.
The endpoint is restricted to actors with the configured `admin` role and reports live counts for
users, sessions, organizations, invitations, queued/dead Jobs, Mail deliveries, Files, and Audit
events.

Counters for disabled modules remain zero and do not query tables that were not installed. The page
links to the detailed API token, organization, audit, and Jobs views generated by the runtime.

When Jobs is enabled, `GET /api/admin/jobs` returns up to 100 recent jobs and supports an optional
`status=queued|running|succeeded|dead` filter. Responses include queue, kind, status, attempt budget,
timing, tenant, and the bounded last error; payloads are intentionally not exposed.

`POST /api/admin/jobs/{id}/retry` accepts only dead jobs. It keeps the original ID, resets attempts,
clears lease/error/completion state, and queues the job immediately. `POST
/api/admin/jobs/{id}/replay` accepts succeeded or dead jobs and creates a new queued row containing
the original payload and execution settings. Replay clears the idempotency key so the new job cannot
collide with the original record.

All Admin endpoints require the `admin` role. Cookie-authenticated mutations also require the
generated CSRF header; Bearer tokens retain their normal Actor authorization. Row locks serialize
retry/replay with competing administrative actions, and queued or running jobs cannot be replayed.
