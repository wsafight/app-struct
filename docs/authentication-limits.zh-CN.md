# 认证与邮件限流

生成的后端使用 PostgreSQL `_appstruct_auth_login_attempts` 记录一分钟固定窗口计数，同一 key 每个窗口最多通过 10 次。窗口从第一次请求开始计算，超过窗口后下一次请求自动重新计数。多个 API 副本共享数据库计数，计数更新是原子的。

| 入口 | key | 消耗时机 |
| --- | --- | --- |
| 登录 | 规范化邮箱 | 格式校验后、密码验证前；成功登录会清除此 key |
| 注册 | `register:<规范化邮箱>` | 凭据格式校验后、密码散列和创建账户前；重复邮箱尝试也计数 |
| 密码重置申请 | `reset:<规范化邮箱>` | 邮箱格式校验后、查询用户前；未知邮箱同样计数并返回通用结果 |
| 验证邮件 | `verify:<用户 ID>` | 颁发验证链接前；注册自动发送与未验证账号的重发共用计数 |

超过限制返回 HTTP 429、错误码 `RATE_LIMITED` 和 `Retry-After: 60`。等待 60 秒后重试即可进入新窗口。已经验证的账号重发请求不会再发邮件。登录成功只清除登录计数，不会解除注册或邮件限制。

这套规则限制单个邮箱或账户的重复请求。它不限制攻击者轮换邮箱，也不从未经信任的 `X-Forwarded-For` 识别来源。对公网部署应在反向代理或网关定义适合流量的来源限额；由部署方明确代理链和真实地址提取规则。个人 Token 管理和租户邀请等已认证入口仍按各自授权及资源规则处理。

回归测试使用两个独立路由实例连接同一 PostgreSQL，覆盖注册、验证邮件、并发密码重置、429 和窗口恢复：

```bash
APPSTRUCT_E2E_DATABASE_URL=<独立测试库> cargo test --locked -p appstruct-codegen --test auth_rate_limit
```
