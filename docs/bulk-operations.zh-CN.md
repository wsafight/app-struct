# 批量操作

每个生成资源都暴露显式的批量和 CSV 端点。当一次请求要改多条记录、并且调用方需要部分失败明细而不是全部成功或全部回滚时，使用这些端点。

```text
PATCH /api/<table>/_bulk
DELETE /api/<table>/_bulk
GET /api/<table>/_export.csv
POST /api/<table>/_import.csv
```

## 逐条结果

批量写入要求每个 id 都有对应的 `expected_revisions` 条目。授权、租户作用域、Policy、字段检查、钩子和审计事件按记录逐条求值。响应始终包含 `succeeded` 和 `failed` 数组，调用方可以只重试被拒绝的记录。格式错误的 id，以及单条记录的钩子、校验、Policy、冲突或数据库失败会用 savepoint 隔离并报告在 `failed` 中；它们不会回滚其他已成功的记录。内部数据库细节只在服务端记录日志，永远不会包含在响应中。

## CSV

CSV 导出使用 API 字段名并包含表头行。CSV 导入接受相同名称，忽略生成列，通过常规创建契约校验每一行，并在提交成功行的同时报告行级失败。Realtime 事件和 `after_commit` 钩子只在外层事务提交后运行。

CSV 导出在 PostgreSQL 的 repeatable-read 只读快照中流式读取，并以 64 KiB 分块发送。支持当前搜索、筛选、`where`、`sort` 和 `fields`；导出完整筛选结果，因此拒绝分页参数。超过 10,000 行会在发送表头前失败，数据库语句超时为 30 秒。支持文件保存 API 的浏览器直接分块写入选定文件，其余浏览器使用 Blob 下载。

## Web 导入与批量处理

导入先显示字段映射和每页 25 行的可编辑预览，不会在选择文件时写入。客户端限制为 2 MiB 和 10,000 行；必填字段、类型与取值错误必须先修正。导入后显示累计成功数和每条剩余行的原因，失败行可以下载或就地修改。重试仅发送剩余行，原始 CSV 记录号用于定位，后端结果 id 是本次提交中从 0 开始的行序号。CSV 表头必须唯一；JSON 单元格按 JSON 值读取，无效 JSON 报行级错误。

批量选择仅限当前页。更新复用表单字段控件和精确标量校验，提交前展示字段值、记录及修订号。结果显示逐条失败原因；重试重新读取可访问记录的修订号，并再次展示确认页面。已成功记录不会进入重试请求。

## 导入批次恢复

每次 CSV POST 必须携带 `Idempotency-Key`，使用随机 UUID v4/v7；**同一份不可变 CSV 只生成一次批次 ID**。生成客户端调用为 `resource.api.importCsv(csv, batchId)`。相同请求并发或重试只提交一次并返回保存的逐行结果；同一 ID 携带不同内容返回 409。结果与业务行在同一事务提交。通过 `GET /api/<table>/_imports/<batchId>` 或 `resource.api.importResult(batchId)` 恢复丢失的响应；404 表示当前作用域下没有可见的已提交批次，仍应使用原内容和原 ID 重试。

批次按资源、操作者和租户隔离。匿名导入没有操作者身份，无法预测的批次 ID 同时承担结果查询凭据的作用。账本只保存内容摘要和结果，不保存 CSV 原文；目前不自动过期。客户端仍可能重放旧 ID 时，不应删除对应账本，否则可能再次导入。这保证请求幂等，业务唯一性仍由业务键和约束保证。

Web 在结果不确定时冻结内容，提供查询结果和同批次重试。首个请求明确返回校验或授权拒绝后可修正；不确定重试会保留原 ID。确认部分成功后，只修正失败行并创建新批次。关闭页面会失去内存中的原始内容；请保留展示的批次 ID，以便通过应用客户端查询结果。浏览器存储不保存 CSV 原文。
